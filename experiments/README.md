# Demand residual correction exploration

This worktree starts from `origin/price-c2` (ad82bc5). The submission packages and trained artifacts have not been changed.

`demand_bias_screen.py` reads saved chronological predictions directly from `origin/feature/demand-mlp` (f92a38e). It selects a same-slot residual correction (28 previous market days, shrinkage 0.5) using 2015–2020, then evaluates 2021–2024 and the previously inspected 2025–October 2026 period. It also tests a stateless anchor-error proxy, which did not generalize. Run with Python, NumPy and pandas:

```
python experiments/demand_bias_screen.py
```

`results/codex_demand_bias_screen/` contains the screens and the same-model proxy, including paired seven-day block-bootstrap intervals. The proxy excludes the first 28 days after every recorded model refit: outside those periods the saved forecasts were generated by the same model as the current forecast. This is not an end-to-end replay of the new code; all later periods have been inspected previously. Days immediately following training are excluded, so the summary is not directly comparable to a full-period score. Bootstrap intervals are exploratory, and do not correct for selection or prior reuse.

`demand_bias.py` is a standalone implementation that reconstructs prior forecasts in batch from history, and uses no correction when the 28-day window overlaps training. `demand_bias_runtime.py` loads the original frozen blend from the branch, checks feature parity on four days, checks the correction and fallback, and times the prototype. It requires the pinned Python 3.11 packages and reads the artifact blobs through Git:

```
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=2 python experiments/demand_bias_runtime.py
```

The timing is a local calculation, not an official whole-package runtime or memory check. Before adopting, replay the actual prototype on historical refits (including fallback at boundaries), verify cutoff provenance, run the full submission checker, rebuild the exact combined demand/C2 package, and test memory and reproducibility. Avoid fitting or selecting using live-week data.

Price: `results/price_v3_final/frozen_selection_round2.json` selects C2 at a 0.50 threshold using a three-seed comparison. Its candidate recipe lists five seeds conditional on rebuild budget; the reported performance is for three, not five. No C2 fitted artifact or complete combined package is committed on this branch. The nine existing `code/price_v3/test_v3.py` tests passed in a Python 3.11 environment with pinned required numeric packages.
